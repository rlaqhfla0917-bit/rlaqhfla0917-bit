# FabPulse | 프로젝트 정의서

## 1. 해결하려는 문제

반도체 제조 과정에는 매우 많은 익명 측정값이 기록되지만, 이 모든 측정값을 동일한 우선순위로 해석하는 것은 비효율적입니다. 공개 SECOM 데이터는 1,567건의 샘플 중 불량이 104건으로 적어 단순 분류 정확도만으로 모델 가치를 평가하기 어렵습니다.

**연구 질문:** 590개의 과거 측정 변수로 샘플 위험도를 산출하여 상위 10%만 선별할 경우, 무작위 점검보다 실제 불량 샘플을 더 많이 찾아낼 수 있는가?

이는 점검 인력이 실제로 10%라는 주장이 아니라 **검토 자원이 제한된 운영 상황을 가정한 평가**입니다.

## 2. 데이터 증거 표

| 항목 | 실제 확보 가능한가? | 분석에 활용하는 방식 | 한계 |
|---|---|---|---|
| 제조 측정값 590개 | 있음 (`secom.data`) | X 피처 | 익명화, 일부 결측 |
| 양품/불량 판정 | 있음 (`secom_labels.data`) | y 레이블 (양품 -1, 불량 +1) | 정답은 과거 검사 결과 |
| 검사 시각 | 있음 (`secom_labels.data`) | 시간순 데이터 분리 | 생산 공정별 입력 시각 아님 |
| 불량 주요 요인 후보 | 학습 후 추정 가능 | 변수 중요도 | 인과 관계 또는 물리적 원인 확정 불가 |
| 제조 장비 ID | 없음 | 활용 안 함 | 장비별 고장 탐지 불가 |
| 구체적 센서 이름과 단위 | 없음 | 활용 안 함 | 온도·압력 등으로 해석 불가 |
| 실시간 센서 데이터 | 없음 | 활용 안 함 | 실시간 예측·제어 불가 |
| 점검 인력·비용, 조치 이력 | 없음 | 10% 가상 시나리오 | 실제 비용/수율 개선 효과 산출 불가 |

## 3. 산출물

- `train.py`: 시간순 데이터 분할 및 학습·최종 테스트 평가
- `artifacts/metrics.json`: 모델 선정 결과 및 보류 테스트 지표
- `artifacts/test_predictions.csv`: 테스트 샘플 위험도 순위 및 정답
- `artifacts/feature_importance.csv`: 중요 변숫값과 산출 방식
- `app.py`: 다양한 점검 비율별 불량 포착률 대시보드

## 4. 실험 설계

- **Baseline:** 무작위 점검 시 기대 불량 포착률은 점검 비율과 같습니다. 상위 10%를 점검하면 평균적으로 전체 불량의 약 10%를 포착할 것으로 기대합니다(정확히 10%를 포착한다는 의미가 아님).
- **Model:** Logistic Regression vs Random Forest; 학습 과정의 결측치 대체·상수 변수 제거·변수 선택은 학습 집합 내부에서만 수행.
- **Selection:** 검증 구간에서 Recall@10%가 큰 모델 선택. 동률이면 AP.
- **Final:** 독립적인 시간순 마지막 20% 테스트로 모델을 평가.
- **Report:** Recall@10%, Precision@10%, Lift@10%, AP, 무작위 기준. 작은 양성 표본 수에 따른 통계적 불확실성과 과거 데이터 특성을 명시.

## 5. 완료 판정 기준

1. 공식 출처 파일과 SHA256이 일치해야 합니다.
2. 실제 테스트 데이터에서 예측값과 주요 지표가 재현 가능해야 합니다.
3. 전체 샘플 중 상위 점검 대상이 바뀔 때 불량 포착률이 실시간으로 변하는 대시보드가 작동해야 합니다.
4. 결과는 무작위 점검 대비 좋거나 나쁜 점 모두 그대로 보고합니다. **성능을 만들어내지 않습니다.**
5. 차후 새로운 데이터로 검증할 필요가 있음을 명시합니다.

## 6. 자기소개서에 쓸 수 있는 범위

현재: 공개 반도체 제조 데이터 기반의 품질 점검 문제정의, 분류 학습과 평가 파이프라인 개발, 모니터링 프로토타입 제작.

공식 데이터 학습과 검증 후: **실제로 나온** 보류 테스트 성능 수치를 추가 가능.

금지: 실제 현장 수율/불량률 향상, 특정 원인 발견, SK하이닉스 장비 활용, 실시간 조기 경보 성능 등 데이터로 검증할 수 없는 주장.
